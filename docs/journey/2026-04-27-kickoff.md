# 2026-04-27 Kickoff

## What Was Done

- Defined the product as an AI resume-building SaaS for IT and software professionals.
- Chose structured resume JSON as the source of truth.
- Locked the early architecture around Next.js, FastAPI, PostgreSQL, S3, SQS, Bedrock, and export workers.
- Completed Phase 0 documentation.
- Set up the Phase 1 monorepo foundation with frontend, backend, workers, infra folders, and root project files.
- Initialized one Git repository at the root of the project.

## What Was Learned

- The product idea came from a real workflow pain point: editing LaTeX resumes in Overleaf manually is slow and repetitive.
- LLMs can produce much better resume output when constrained by template fit, one-page rules, and deterministic formatting expectations.
- Even if the initial insight came from LaTeX generation, the real product value is broader: resume structuring, editing, targeting, and output quality.

## What Got Blocked

- Docker Desktop became reachable, but the local PostgreSQL image pull failed because Docker could not resolve `registry-1.docker.io`.

## What Changed In The Product

- The project is staying monorepo-based with one root Git repository.
- The docs were reorganized into structured subfolders: planning, architecture, setup, and journey.
- The journey folder is now the place to record daily progress and public-sharing drafts.

## Public Sharing Angle

Strong story:

- This project started from a personal frustration with updating a resume in Overleaf.
- Prompting and agentic code workflows produced better results than generic chat rewriting.
- The next step is turning that personal workflow into a product other people can actually use.
