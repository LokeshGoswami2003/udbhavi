# 2026-04-29 Session 002

## Topic

Current project status, AI JSON vs LaTeX output, migration strategy, agent behavior, and setup flow documentation.

## Questions

1. What has been achieved so far?
2. Why should the AI return JSON instead of directly returning LaTeX?
3. How will database migrations be handled, and are we using Prisma?
4. Should agents automatically agree with product or architecture decisions?
5. Can the project flow be documented clearly for local setup and production?
6. How should the agent behave when implementation begins?

## Answers

1. The project has completed Phase 0 documentation and Phase 1 foundation setup: monorepo structure, one root Git repo, initial Next.js app, initial FastAPI app, root project files, standards docs, journey docs, and QA docs.
2. The AI should return structured resume JSON because it is easier to validate, version, diff, partially edit, and render into multiple outputs. Direct LaTeX output is too brittle as the primary system contract.
3. The backend will use SQLAlchemy and Alembic. Prisma is not part of the chosen stack because the backend is Python/FastAPI, not a Node backend.
4. No. Agents should not automatically agree. They should reason through tradeoffs and push back politely when a decision weakens the architecture or maintainability.
5. Yes. The setup docs were expanded with local flow, production flow, commands, and diagrams.
6. The agent should explicitly tell the user when implementation is starting, ask for user input when a decision materially affects the implementation, and document the changes and decisions in the same session.

## Decisions Taken

- Keep JSON as the primary AI contract.
- Keep SQLAlchemy and Alembic as the Python ORM and migration stack.
- Strengthen AGENTS instructions so agents reason instead of agreeing automatically.
- Expand setup documentation with stepwise flow and diagrams.
- Require explicit implementation-start communication and decision check-ins when needed.
