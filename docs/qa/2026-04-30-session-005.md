# 2026-04-30 Session 005

## Topic

Finalizing the current local setup contract and tightening the auth/workspace UX before closing the phase.

## Questions

1. Which local frontend port should be treated as the fixed project default?
2. Should local development continue using Docker Compose PostgreSQL?
3. How should the provided Neon connection string be used with the Python backend stack?
4. What should the auth and first workspace screens optimize for right now?

## Answers

1. Local web development should run on port `3000` only.
2. No. Local development should use Neon PostgreSQL instead of Docker Compose Postgres.
3. The backend should use the SQLAlchemy-compatible `postgresql+psycopg://...` form of the Neon URL, with the SSL settings preserved.
4. The first-run UX should stay focused, responsive, and short: only purposeful copy, a clear next step after auth, and no filler sections that create unnecessary scroll.

## Decisions Taken

- Pin the Next.js local scripts to port `3000`.
- Remove the stale Docker Compose Postgres setup from the active local-development path.
- Store the Neon connection in the ignored backend `.env` file and keep the example file sanitized.
- Reduce workspace-entry content to one clear action area plus a compact explanation of the immediate journey.
- Split auth workspace logic into smaller components and a dedicated session hook to preserve modularity.
